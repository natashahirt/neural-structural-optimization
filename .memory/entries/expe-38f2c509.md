Scoping stage 3. The two repos ship a function of the same name that describes a different structure, so compliance numbers across the repos have never been comparable.

VENICE (neural_structural_optimization/problems.py:447):
  normals[:, -1, Y] = 1
  # normals[-1, :, X] = 1        <- deliberately commented out
  forces[:, ::interval, Y] = -1 / width      # interval=64 in the golden run

HARDFORK (neural_structural_optimization/structural/problems.py:685):
  normals[:, -1, Y] = 1
  normals[-1, :, X] = 1          <- ACTIVE
  story_height = height // num_stories       # num_stories=16
  for story in range(num_stories): forces[:, story*story_height, Y] = -1/width

MEASURED at 128x256, uniform density 0.3, both on hardfork's engine so only the problem definition varies:
  venice interval=64, no wall        5 loaded rows   total load  5.0391   compliance  563.80
  venice loads + hardfork wall       5 loaded rows   total load  5.0391   compliance  563.43
  hardfork num_stories=16 + wall    16 loaded rows   total load 16.1250   compliance 7025.99
  hardfork loads, no wall           16 loaded rows   total load 16.1250   compliance 7031.66

SO THE TWO DIFFERENCES ARE WILDLY UNEQUAL IN IMPORTANCE:
- The right-wall constraint changes compliance by 0.07%. It is effectively inert.
- The load pattern changes it by 12.5x. Venice's interval=64 puts loads on 5 rows (indices 0,64,128,192,256, including the supported row); hardfork's num_stories=16 puts them on 16 rows (0,16,...,240) and never on the supported row. 3.2x the total load.

CONSEQUENCE FOR PARITY: the golden target of compliance 73.997 is only meaningful against Venice's interval formulation. Reproducing it requires porting that load pattern, NOT merely matching hyperparameters. Any earlier comparison of hardfork's compliance against Venice's was comparing incommensurable quantities, which is a strong candidate explanation for 'the refactor produced worse results'.

WHY THE RIGHT WALL EXISTS, and why removing it is safe for compliance: Venice's boundary conditions leave X unconstrained everywhere, so the stiffness matrix is SINGULAR - a free rigid-body translation in X. CHOLMOD refuses it outright (CholmodNotPositiveDefiniteError); SuperLU returns one arbitrary solution from the solution family. This is almost certainly why the wall was added. Crucially the singularity does NOT invalidate Venice's result: every force is vertical, so the load vector is orthogonal to the X-translation null space, and the compliance functional f^T u is invariant to the null-space component even though u itself is not unique. Venice's 73.997 is therefore a well-defined number. But it can only be recomputed with a solver that tolerates a singular-but-consistent system (SuperLU), or by adding the inert wall to regularize it.
