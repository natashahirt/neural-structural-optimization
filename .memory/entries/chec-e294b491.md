TWO PREMISES IN THE STAGE-1 PLAN WERE WRONG
- The plan said the cone filter is column-normalized and sum-preserving so volume survives filtering. It is not. On the legacy path the achieved volume fraction is 0.500016188701 against a 0.5 target, an error of 1.6e-5. Legacy runs have ALWAYS missed volfrac slightly. The new enforce-last path achieves ~5e-14.
- The plan predicted the bisection bracket would be the likely silent failure. It was not: the saturation bracket is provably sound (measure(all-ones) is exactly 1.0 even with masks, so it cannot fail for volfrac in (0,1); tested to volfrac 0.95, logit scale 1e7, and all 14 non-trivial-mask problems).

WHAT THE CRITICS CAUGHT THAT NOBODY ELSE DID
- Pass 1, P0: making filter_width finally reach physics would have SILENTLY DISABLED the density filter for the shipped config. script/run.py had rmin=0.25, resolving to radius 0.5, and any radius <= 1.0 makes the cone filter exactly the identity (independently confirmed: max|filtered-input| is 0.000e+00 at 0.5 and 1.0, 6.19e-01 at 2.0). A successful plumbing fix would have looked like a mysterious quality regression. Fixed by setting rmin=1.0 (user decision) so the shipped config resolves to the legacy 2.0, plus a guard making the degenerate case impossible to ship silently.
- Pass 2, P0: the pass-1 remediation was validated at volfrac == eta == 0.5, the SINGLE point where Heaviside projection is mean-neutral. Off that diagonal the render volume gap is +19.9% (volfrac 0.3, beta 4), +37.0% (volfrac 0.3, beta 16), +191.7% (volfrac 0.1, beta 16). Deferred to stage 4 as note-cd383274.
- Pass 2 also caught that the new guard was a DEFAULT-PATH regression: it raised inside PixelModel.upsample, discarding a trained stage, because _set_analysis_factor divides rmin by the analysis factor. Fixed by clamping on the derived analysis grid while keeping the hard raise for user config.
