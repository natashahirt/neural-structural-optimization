Successor to E1's dream stage, motivated by expe-41216fc2. That run showed a 16x8 coarse control field DOES fix grain (neighbor_contrast_ratio 0.0907 vs 1.05 for direct pixels) but produced 14 connected components with top_to_bottom_connected=0. E1 treated connectivity as a post-hoc GATE and failed it. E1b moves connectivity into the OBJECTIVE so the optimizer produces spanning silhouettes by construction.

WHY A SEPARATE NON-STRUCTURAL STAGE. Observed: the whole-building CLIP dream produces space-filling texture, not a single large object (see clip_dream_layout_whole_butterfly_wing_venation/dream_coarse.png). Mechanism: CLIP's embedding behaves like a bag of patches and its similarity has no term distinguishing one skull from a hundred; a field where every patch carries the prompt's local features scores higher than one correctly-shaped object, so gradient descent finds the tiling every time. CLIP will not supply large-scale shape coherence because nothing in its objective asks for it. Caveat: the evidence above used 'butterfly wing venation', which is itself a texture prompt, so it is illustrative of the mechanism rather than proof for object prompts.

KEY ARCHITECTURAL DECISION - THE INTERFACE IS A SKETCH. Stage A emits its output in the same format stage6_sketch_on_golden.py already consumes. The downstream half (scaffold -> apply_scaffold_as_occupancy_prior, anneal 4000->400, init_from_occupancy) is already proven by SUCCESS_sketch_to_structure and needs zero changes. This also yields a free control: identical downstream code can consume a human sketch or a CLIP silhouette, so the human sketches are the positive control and any difference is attributable to the silhouette itself.

STAGE A (new, no FEA, standalone script for a seconds-long iteration loop; kept out of clip_dream_layout.py so its tautology gate and Stage 6 machinery are not dragged in):
- Parameterize a low-resolution field at the domain's TRUE aspect (start 32x64). Resolution is the PRIMARY feature-size control: at low resolution fine texture is unrepresentable, a harder guarantee than a tunable penalty weight. Sweep 32x64 / 48x96 / 64x128.
- Forward: raw logits -> Gaussian filter -> heaviside project (existing projected_density_view / sigma_for_min_feature).
- Render for CLIP by LETTERBOXING into a square canvas padded with BACKGROUND (not material). CLIP's ViT needs square input; cropping is what the user rejected as non-generalizing, and squashing distorts (a 2:1-squashed skull unsquashes into a stretched skull no human reads as a skull). Letterboxing keeps true proportions, and the largest motif that fits is then bounded by the short side - the honest reading of 'largest features that fit', and it generalizes to any domain the structural problem dictates.
- Losses: CLIP + volume-fraction target (weighted hard, as a constraint, so it cannot satisfy the prompt by flooding) + perimeter/TV (secondary dial, consolidates many small blobs into few large ones at fixed volume) + CONNECTIVITY TO THE SUPPORT BOUNDARY (the critical term, per expe-41216fc2).
- Set the volume target to the value the structural run will actually use.

STAGE B: bilinear upsample via resample_field to 128x256, then RE-APPLY the heaviside at target resolution to re-crisp. Without the second projection the upsample reintroduces the gray boundary that filter-then-project was built to remove.

STAGE C: existing pipeline untouched. Live-CLIP-during-physics deliberately deferred to a switch; the delta between annealed-prior-only and annealed-prior-plus-live-CLIP is itself the measurement of whether physics erodes the motif.

MEASUREMENT: compliance vs the compliance-only baseline; mass_fraction_on_occupancy for whether material landed on the silhouette; strain-energy participation through the motif region for whether it carries load (this is what separates structure from decal, and is now computable post-hoc from physical_density.npy without a re-run).

GATES (stop early rather than spend an FEA run):
1. After Stage A: does the PNG read as a skull? Human judgment, no metric, no FEA. If no resolution or weighting produces a recognizable silhouette, STOP - the user has pre-accepted that as a finding.
2. After Stage A: top-to-bottom spanning component required (the gate expe-41216fc2 failed).
3. After Stage B: crisp and connected to supports.
4. Only then run physics.

USER CONSTRAINTS CARRIED FORWARD: no AI-generated stencil images (anno-4676f76b); keep the domain aspect dictated by the structural problem rather than choosing a square to suit CLIP; physical-density CLIP polarity; Venice golden stays bit-identical when the prior is off.

SEQUENCING: user wants to validate Stage A working before moving on. The compliance-only baseline is still worth running in parallel since its sensitivity field is how a surviving motif is later judged as sitting in idle material vs the working load path.
