GOAL: reproduce the 250214 skeleton golden run in hardfork under matched semantics, and lock it as a deterministic regression baseline. This is the stage that answers whether hardfork can match legacy at all; every later stage needs this baseline to attribute quality changes against.

DESIGN DECISION taken up front: everything Venice-compatible lands behind an explicit COMPATIBILITY PRESET rather than replacing hardfork's richer path. The stated aim is to BEAT legacy, not merely match it, and that judgement requires both paths runnable side by side. Replacing would destroy the comparison.

THE TARGET (semantopology_venice/results/250214_skeleton_loss_test_balanced_dynamic): model Ada, lr 0.2, clip_alpha 10, compliance_weight 1, num_augs 32, seed 12, CPU, ViT-B/32, penal 3.0, filter_width 2.0, multistory_building 128x256 volfrac 0.3 interval 64, prompt 'skeletons', initial image resources/input_images/dSketches/thick_outer_lins.png inverted. Converged at iteration 124 of 200 max. Final compliance 73.99691670938864, clip_loss_raw 0.3829488754272461, total 357.75022597425567. The log records the FULL loss trajectory at a 5-step cadence, so parity is checked as a CURVE, not an endpoint.

FIVE GAPS, from the scoping pass:
1. CLIP input representation - Venice feeds CLIP the RAW forward output (no sigmoid, no filter, no mask, no volume constraint); hardfork feeds sigmoid(logits) through a multi-view patch pyramid with x100 scaling and an edge regularizer. Highest risk: it dominates the semantic gradient.
2. Loss algebra - Venice's clip weight is compliance * clip_alpha, UNDETACHED, and its total adds the raw CLIP loss on top of the weighted one. Verified against the log: 283.3703603894398 / 0.3829488754272461 = exactly 740.0, and 73.997 + 283.370 + 0.383 = 357.750. Hardfork detaches and uses an inverse-normalized weight.
3. No Ada model - the progressive schedule, its compliance-plateau upsample trigger, and the convergence_threshold stop that produced 'iteration 124' do not exist in hardfork.
4. Image init - the asset EXISTS (venice/resources/input_images/dSketches/thick_outer_lins.png, tracked in venice commit 97f9336; an earlier report that it was missing was wrong). But Venice initializes z in [0,1] PIXEL space while hardfork initializes in LOGIT space, and invert_image is unwired.
5. Determinism - Kornia augmentation RNG is unseeded in BOTH repos, so bit-exact replay is not realistic. Parity must be statistical against the logged curve.

PREREQUISITES CLEARED BEFORE THIS STAGE COULD START: the CHOLMOD OpenMP segfault at 128x256 (expe-37cbb8da) and the multistory_building load-pattern divergence (expe-38f2c509). The latter matters enormously for interpreting this stage - compliance figures across the two repos were never comparable, which is a leading candidate explanation for 'the refactor produced worse results'.
